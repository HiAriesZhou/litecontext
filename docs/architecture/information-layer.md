# Information layer

LiteContext is one local product and one repository. Knowledge, Memory, and Context are capability domains over a shared evidence foundation. They are not separate products. This page is the current target. The file-based evidence core described in [Architecture](overview.md), the session stdio contract, task checkpoints, explicit memory changes, `lc host hook`, and the read-only `lc inspect` report are implemented. The hook command does not install or edit host configuration. `lc inspect` reads stored records and does not start a service; it is not the viewer. `lc view` writes one self-contained HTML file from the stored records and source list, then exits. It does not change memory. CI runs the Go suite on Windows. That covers the native lock, bundle commit, and stdio contract. A Windows agent hook has not been observed. The evidence core also runs on macOS and Linux.

## Capabilities

| Domain | Records | Update rule |
| --- | --- | --- |
| Knowledge | Source material and summaries derived from an exact source version | Refresh when the source version changes |
| Memory | Scoped decisions, preferences, constraints, and experience | Revise only with evidence, correction, supersession, or expiry |
| Context | The selection prepared for one task and its delivery record | Rebuild for each preparation |
| Task state | Goal, progress, checks, blockers, and the next step | Keep temporary; do not promote it to memory automatically |

Knowledge and Memory both supply Context. A changed document updates Knowledge. It does not overwrite a project decision. Context may select the new document, the current decision, and the task state together.

The default delivery is small: current constraints, task progress, and an index of what can be retrieved. The agent retrieves more when the task needs it. Source text and earlier model output are data. They do not grant permission to change host instructions.

## Session contract

`lc serve --bundle DIR` reads one JSON object per line and writes one JSON object per line. `--once` handles a single request. Every request includes `"version": 1`, and every response returns that version. A missing or different request version is rejected. The fields are [request.schema.json](../../contracts/session/v1/request.schema.json) and [response.schema.json](../../contracts/session/v1/response.schema.json). The inspect result shape is [inspect-report.schema.json](../../contracts/session/v1/inspect-report.schema.json). The prepare result shape is [prepare-pack.schema.json](../../contracts/session/v1/prepare-pack.schema.json). Each search hit and the show result use [evidence.schema.json](../../contracts/session/v1/evidence.schema.json). Search returns an array of those objects, including an empty array when nothing matches. Show returns one object. A prepare entry ref omits an empty record hash or line range. A search or show ref includes those fields. `record` returns the event object, `checkpoint` returns the task object, and `memory` returns the memory object from the inspect report. `deliver` has no result object. The operations are `search`, `show`, `record`, `prepare`, `deliver`, `checkpoint`, `memory`, and `inspect`. `record` stores an event under the bundle's local `events` directory and does not add evidence. A repeated event ID with the same content is a replay; the same ID with different content is rejected. `prepare` selects task text, pinned evidence, and search hits without calling a model. A prepared entry includes the evidence locator when it has one. Entries that do not fit the rune budget are omitted whole. Unavailable pins are omitted without their text. `deliver` stores the rendered `text`, the `selected` and `emitted` entry counts, optional `elapsedMs`, and the optional identity of each emitted entry under `events/delivery/<eventID>.json`. An identity is the role, locator, and ref. It does not copy the entry body. A missing `entries` field means those identities are unknown. An empty array means nothing was emitted. More than 100 identities, or a list that does not fit in the delivery file, keeps a shorter prefix and sets `entriesTruncated`. When no identity fits, the array is empty and `entriesTruncated` is still true. The delivery is rejected instead of omitting `entries`, so a truncated record is not stored as an old record. `elapsedMs` is an integer from 0 through 600000. A record written before `elapsedMs`, omissions, or entries existed still reads. The same event ID replaces that record. Acknowledgement and use stay `unknown`. `checkpoint` replaces the current task: goal, progress, checks, blockers, and the next step. An empty task removes it. `prepare` uses the stored task when the request omits `task`; an explicit task applies only to that preparation and does not change the stored one. A checkpoint that cannot be read is omitted. It is not evidence and it is not memory. `memory` proposes, confirms, corrects, supersedes, or revokes a cited conclusion. A proposal is not selected. Confirming it makes it eligible. Superseding or revoking it removes it from the current selection immediately. The replacement is not current until it is confirmed. A memory can cite evidence that is not in the bundle. It does not become evidence, and a task checkpoint is not promoted to memory. `inspect` returns the snapshot generation, the source id, name, type, update time, and active state from that snapshot, the current task, every stored memory, the active memories, events, deliveries, and fixed failure tokens for sections that cannot be read. Generation labels that source list. If the snapshot cannot be confirmed unchanged before the report is finished, the failure token is `snapshot changed`. That confirmation reads the snapshot hash, not the snapshot body. It does not write a second store, call a model, or start the viewer. `lc inspect` prints that report, and the session operation returns the same report.

## Modules

A new agent client adapts the host. It does not receive a copy of retrieval, memory, or storage rules.

| Module | Responsibility | Depends on |
| --- | --- | --- |
| Contracts | Versioned JSON for events, search, context packs, and delivery records | Nothing host-specific |
| Evidence core | Records, citations, versions, scope, and the file bundle | Contracts |
| Context assembly | Selects and sizes a pack for one task | Evidence core |
| Memory | Proposals, correction, supersession, and activation | Evidence core |
| Session runtime | Serves the contract over stdio and owns no host rules | The modules above |
| Host adapter | Maps one client's events and injects the returned pack | Session runtime |

Knowledge remains the evidence core's retrieval view. The viewer and CLI call the same runtime. Neither keeps a second copy of the records.

The host contract has eight operations: record an event, prepare context, search current evidence, show an exact version, record the injected text with its selected and emitted counts and optional elapsed time, replace the current task checkpoint, change a memory explicitly, and inspect the stored records. `inspect` is read-only and is not the viewer. Session start, prompt submission, stop, and compaction are host details mapped onto those operations. An adapter can be written in the host's own language because the contract is JSON over stdio, not a Go API.

## Runtime and platforms

Command hooks start a new process for each event. They do not keep a process warm. The first read in that process parses the snapshot. A later read in the same process reuses it until `HEAD` changes. A prompt without pins searches once, so that reuse does not remove the usual cold parse. The next hook event is a new process and parses again.

A one-shot read holds the bundle lock only while copying the current snapshot and removing non-current snapshot files. Parsing and search run after the lock is released, so one hook does not wait for another hook to finish parsing. A write holds the lock through the commit. A hook must not wait out the two-second bundle lock. Prompt injection gives up after 200ms. Session start gives up after one second. For Codex and Claude Code, giving up means exit 0, empty stdout, and one stderr line. Gemini events give up with exit 0 and empty stdout and stderr. Gemini reads a successful hook's stdout as JSON, and stderr from a non-zero exit can become a failure reason. `--host gemini` uses that silence for every event and injects only `BeforeAgent`. `--host codex` and `--host claude` do not accept Gemini events. Exit 1 is only for command misuse. There is no machine-wide daemon and no network listener. A helper that stays up for the host session is not part of this stage: it would be a background process, and it waits until a measured one-shot prepare misses the deadline above.

macOS is the first host target, using the existing file-lock implementation. Windows is the second and must be native. A Windows agent does not reliably share paths, hooks, and process state with WSL2, so WSL2 is not the product path. The Windows build uses `LockFileEx` for the bundle lock and the event lock. Atomic replacement of `HEAD` uses the Go 1.26 `os.Root` rename, which replaces an existing file. CI runs the suite on `windows-latest`. A Windows agent hook has not been observed. Codex on Windows selects `commandWindows` when it is present. The Codex fragment from `lc host example` includes that field only on Windows, using the executable path from that machine. Claude and Gemini fragments never include it. Linux can keep the current lock implementation, but it is not a product target.

One-shot preparation stays on the machine that holds the project files. It does not call a model or use the network. Opening the committed snapshot dominates a cold hook. The first read in a process parses it once and keeps the canonical bytes so an unchanged snapshot is not serialized again. A later read reuses that parsed snapshot without copying it. A write copies the snapshot, including nested extension values, before changing it. A returned source record copies those values too. Duplicate keys and a record hash that does not match its text are still rejected. The host stops a prompt hook at 200ms. A cold Codex hook over 200 notes on one macOS machine returned in 22-29 ms. A shared CI CPU can take longer, so CI only fails this hook when it exceeds one second. Retrieval stays literal while search is not what misses the host budget. A rebuildable index is considered only when search itself misses that deadline. The index candidate is pure-Go SQLite, because a CGO SQLite build makes Windows compatibility worse. A vector database, reranker, and knowledge graph are not required for the first host integration.

## Technology choices

| Area | Choice | Reason |
| --- | --- | --- |
| Language | Go, no CGO | One native binary for macOS and Windows |
| Storage | File bundle behind one storage interface | Keep the current authority while isolating platform locks |
| Host boundary | JSON stdio, eight operations at version 1 | A client can integrate without linking the core |
| Process | One-shot process per hook event; `lc serve` only when a client holds it | Command hooks cannot keep a warm process |
| Retrieval | Literal search until search itself misses the 200ms prompt budget | Snapshot loading was the cold-hook cost, not search |
| Model use | Off the delivery path | Host hooks cannot wait for extraction |

Model extraction waits until delivery can be checked. A later model task has explicit limits on calls and size. If no model is available, source retrieval, existing memory, and task state still work.

Capacity is calculated from the content prepared for the host, not from the number of search hits. A delivery record distinguishes selected, emitted, acknowledged by the host, and shown by evidence to have been used. A state the host cannot prove remains unknown.

The current snapshot limit of 64 MiB is for a bounded evidence collection. Continuous session capture requires append-only records before it is enabled.

## Host hook

`lc host hook --bundle DIR [--host codex|claude|gemini]` reads one hook JSON object from stdin. The selected profile decodes that input and encodes the injection. Codex, Claude Code, and Gemini CLI currently share one JSON envelope; accepted events and stderr silence stay on the profile. It does not install or edit host configuration. `lc host example --bundle DIR [--host codex|claude|gemini]` prints a hook fragment for the current executable and that bundle. It does not write the file or install the hook. The default host is Codex. Codex paths are shell-quoted. Claude passes the executable and arguments separately, without a shell. Gemini uses one shell command. No fragment sets a matcher, so a Codex or Claude `SessionStart` also runs after compaction. The Codex fragment includes `commandWindows` only when the example runs on Windows. Codex allows at most 3 seconds for `SessionEnd`, so that event uses 3. Its other events and every Claude event use 10 seconds. Gemini lists only `BeforeAgent` and sets the timeout to 10000 milliseconds. The process still abandons a prompt after 200ms and any other event after one second. Without `--host`, `SessionStart` maps to `session_start`, `UserPromptSubmit` and Gemini CLI `BeforeAgent` to `prompt`, `PreCompact` to `compact`, and `Stop` or `SessionEnd` to `stop`. `--host gemini` maps only `BeforeAgent` to `prompt`. `PreCompress` is not an alias of `PreCompact`. Any other event is ignored.

The event body is the prompt, or a short source token such as `startup`. `cwd` and `transcript_path` are not stored. The event ID is `hook_` plus the SHA-256 of the kind, session ID, and body. The same payload replays; a different body is a different event.

A prompt event sends the raw `prompt` to `prepare` and does not send `query` or `terms`. `prepare` keeps at most four distinctive terms from that prompt. Common English question words are left out. The selected terms are searched in one pass, and an item matches when it contains any of them. A long uninterrupted string, including Chinese text, is sampled as short windows. Explicit `query` and `terms` remain available for a caller that already chose them. A request cannot combine `prompt` with either, and `prompt` is valid only on `prepare`. Term selection, retrieval, citation lines, the rune budget, and the stored task belong to `prepare`. The hook records the event and wraps the rendered pack; it does not select terms, search, or save a task on its own. When the hook does not send a task, `prepare` includes the stored checkpoint. It also includes confirmed memories whose visibility matches the request. A candidate, superseded, or revoked memory is not selected. Session start and a prompt with no search terms still prepare, and they do not invent a query. When it injects text, it calls `deliver` with that rendered `text`, the pack's `selected` and `emitted` counts, `elapsedMs` clamped to 0–600000, the omissions returned by prepare, and the role, locator, and ref of each emitted entry. The record is `events/delivery/<eventID>.json`. Acknowledgement and use stay unknown. A delivery written before omissions were stored still reads. A failure to record delivery still returns the injection. Events without a prompt are recorded and do not invent a query. Without `--host`, injection is written for `SessionStart`, `UserPromptSubmit`, and `BeforeAgent` when at least one rendered entry fits. `--host gemini` injects only `BeforeAgent`. The injected text is that rendered pack, at most 2000 Unicode code points. The JSON contains `hookSpecificOutput.hookEventName` and `hookSpecificOutput.additionalContext`. The text cites a relative locator and line. It is not an instruction. By default the owner's private records are eligible. `--visibility public|team|private` is an explicit filter, not model authorization.

The process accepts UTF-8 JSON, including CRLF and one leading UTF-8 BOM. UTF-16 input is invalid. The process exits 0 with empty stdout when input, the bundle, or the deadline fails. Codex and Claude Code events also write one stderr line. Gemini events do not. `UserPromptSubmit` and `BeforeAgent` wait at most 200ms. Any other known event waits at most 1 second. Exit 1 is reserved for a malformed command, including an unknown `--host`. Windows hook behavior has not been run on Windows.

## Prototype

The prototype checks one software project handed between Codex and Claude Code. It uses synthetic project material. It does not import personal data, scan a whole account, or activate memory automatically.

`TestPrototypeHandoffKeepsCurrentConstraints` runs that sample: a changed document, a superseded decision, a changed working file, a duplicate event, and a rejected memory update. It prepares knowledge without memory, memory without a knowledge hit, and context composed from the refreshed document, the confirmed memory, and the task. The text injected by the hook is the stored delivery.

`lc inspect` prints the stored report. `lc view --bundle DIR --output FILE` writes one self-contained HTML file and exits. The file is not a service, has no write controls, and does not change memory. The writer creates a new file in the destination directory and renames it into place. It refuses a symlink or non-regular path. Replacing a hard-linked name leaves the original file unchanged, including when that file is inside the bundle. It has four sections:

1. Sources, shown by id, name, type, active state, and update time, with the stored task and stored read failures. Connected hosts, selected files, and collection failure are unknown.
2. Stored delivery text, selected and emitted counts, elapsed time when it was stored, and each stored omission's role, locator, and reason. When entry identities were stored, each one shows its role, source id, item id, record hash, and locator. A truncated list says so. A delivery written without entries still shows the source version as unknown. Acknowledgement and use stay unknown. A delivery written without omissions still shows that reason as unknown.
3. Each memory with its scope, visibility, and evidence. The next explicit session action is confirm for a candidate; correct, supersede, or revoke for an active memory; and none after it is superseded or revoked.
4. Stored events. A name beginning with a dot, including the Windows event lock, is not an event. Replay and processing stage are unknown.

The prototype is accepted only when the record matches what the host received, required constraints are present, superseded decisions are not presented as current, and the added time stays visible. The macOS path is accepted before the Windows adapter. Windows acceptance includes a native lock, an atomic bundle commit, and the same stdio contract. Knowledge must work without Memory. Memory must accept a cited conclusion without a complete knowledge base. Context must allow either supplier to be replaced.

The stdio contract, deterministic assembly, task checkpoints, the one-shot hook adapter, and the prototype sample are in place. Windows CI runs the suite. A Windows agent hook has not been observed. Model extraction and an extra index come after search itself misses the hook deadline.
